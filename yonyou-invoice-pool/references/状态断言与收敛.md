# 状态断言与收敛协议

> 本文件解决一个具体问题：**录入过程中一旦出错，就会原地打转。**
> 2026-10-23 的一次脱敏票袋实跑中，22 分钟里调用了 **106 次** Tabbit 脚本，
> 真正推进业务的动作只有 **9 次（8.5%）**，其余 64% 都耗在"定位当前在哪、纠上一次的错"。
> 不是页面不稳定，是动作没有前置断言，失败后的恢复动作又把状态推回了出问题的起点。
>
> **执行本 skill 第 4 步之前必须先读这一份。** 下面的断言不是建议，是硬性前置条件。

---

## 一、先把页面当成状态机

录入过程中只存在四个状态。**每发一个写操作前，先判定当前态；态不对，先修态，绝不硬动作。**

| 态 | 名称 | 判定表达式 |
|---|---|---|
| `S0` | 票袋列表 | `document.querySelectorAll('.wui-table-body tr').length > 0` 且无 `.wui-modal` |
| `S1` | 类型选择弹窗 | 最上层 modal 文本含「请选择添加票据信息」或「请选择发票类型」 |
| `S2` | 票据明细表单 | 存在 `[fieldid="znbzbx_tallydata\|nmny"]` |
| `S3` | 附件面板 | 最上层 modal 文本含「原文件目录」或「已选 N/M」 |

合法迁移只有：

```
S0 --发票采集/手工录入--> S1 --下一步--> S2 --附件--> S3 --关闭--> S2 --保存--> S0
```

任何一跳不成立，就说明上一步没成功。**此时继续往下点必然超时**（典型：还在 S1 就去点
`dopendate_input`，报 `locator.click: Timeout 10000ms exceeded`）。

## 二、动作前三断言（每条都回读，不看返回值就继续等于赌博）

每次点「下一步」「保存」「移动」「删除」之前，跑一遍：

```js
const wf = page.frames().find(f => f.url().includes('c4.yonyoucloud.com'));
const st = await wf.evaluate(() => {
  const modals = Array.from(document.querySelectorAll('.wui-modal')).filter(e => e.offsetWidth > 0);
  const top = modals[modals.length - 1];
  const txt = (document.body.innerText || '').replace(/\n+/g, '|');
  return {
    modals: modals.length,
    modalHead: top ? (top.innerText || '').replace(/\n+/g, '|').slice(0, 120) : null,
    bag: Array.from(document.querySelectorAll('.ticketBag-item.select')).map(e => e.innerText.replace(/\n+/g, ' '))[0] || null,
    rows: Array.from(document.querySelectorAll('.wui-table-body tr')).filter(e => e.offsetWidth > 0).length,
    total: (txt.match(/小计[^|]{0,20}/) || [])[0] || null,
    attach: (txt.match(/附件\(\d+\)/) || [])[0] || '附件(0)',
    checked: Array.from(document.querySelectorAll('input[type=radio]')).filter(r => r.checked)
      .map(r => ((r.closest('label') || {}).innerText || '').trim().split('\n')[0])
  };
});
```

三条硬断言：

| # | 断言 | 不满足时的处置 |
|---|---|---|
| A1 | **弹窗层数 === 预期**（S1/S2 期望 1 层，S3 期望 2 层） | 多了就循环关最上层 `uf-close`；少了说明弹窗被关了，回到 S0 重开 |
| A2 | **`.ticketBag-item.select` 名称 === 目标票袋** | 重新点左栏票袋（先 `scrollIntoView`），否则保存必然落「未分组票袋」 |
| A3 | **目标行金额 / 附件数 === 期望** | 说明点到了别的行，重新按金额定位，**不要按坐标** |

> 血的代价：`.ticketBag-item.select` 没校验，本次有 **25 次**操作涉及「未分组票袋」，
> 两行保存后要额外搬一次家。

## 三、定位器规范：只用业务身份，禁用坐标与序号

### 3.1 列表行：禁止 `page.mouse.click(520, 固定y)`

行高会变、表格会滚、删行后整体上移。固定 y 在页面一变之后指向的就是**另一行**。
本次 `chk2.js` 用 y=393 读住宿行，实际读到了 `附件(11)` 的错位行；`enum.js` 连跑 3 次结果互不一致。

改成按金额（或备注关键词）定位 `tr`，再用它自己的 boundingBox 算坐标：

```js
const pos = await wf.evaluate((amt) => {
  const tr = Array.from(document.querySelectorAll('.wui-table-body tr'))
    .filter(e => e.offsetWidth > 0)
    .find(t => (t.innerText || '').includes(amt));
  if (!tr) return null;
  tr.scrollIntoView({ block: 'center' });
  const b = tr.getBoundingClientRect();
  return { x: Math.round(b.x + b.width / 2), y: Math.round(b.y + b.height / 2), txt: tr.innerText.replace(/\n+/g, '|') };
}, '1,234.56');
if (!pos) return { err: 'row-not-found', amt: '1,234.56' };
await page.mouse.click(pos.x, pos.y);
```

**定位失败就返回 `row-not-found` 并停**，不要退化成"再点一次上次的坐标"。

### 3.2 附件 file input：禁止 `find(e => e.multiple)` 直接取第一个

附件面板是**叠加**的，旧面板的 input 仍在 DOM 里。取第一个 = 把文件传到上一行
（本次住宿行被塞进 11 份，接机/Grab 各 0 份）。

```js
const inp = (() => {
  const all = Array.from(document.querySelectorAll('input[type=file][multiple]'));
  const visible = all.filter(e => {
    const p = e.closest('.wui-modal');
    return !p || p.offsetWidth > 0;
  });
  return visible[visible.length - 1] || null;   // 取最上层那个
})();
```

### 3.3 按钮：禁止用「第 N 个 button」

一律按可见文本精确匹配 + 限定在最上层 modal 内：

```js
const btn = (() => {
  const ms = Array.from(document.querySelectorAll('.wui-modal')).filter(e => e.offsetWidth > 0);
  const scope = ms[ms.length - 1] || document;
  return Array.from(scope.querySelectorAll('button')).find(b => (b.innerText || '').trim() === '保存');
})();
```

## 四、上传必须有完成判据（不能只靠 sleep）

`setInputFiles()` 在此环境会挂起，只能用 JS 注入 `DataTransfer` + `change`。
注入本身**没有完成回调**，`waitForTimeout(6000)` 只是猜。猜短了文件没落库，猜长了浪费时间，
**而且猜错不报错**——这是附件串行能一直藏到复核阶段的原因。

正确做法：注入后**回读文件名清单**，与期望清单逐项比对，不全就再等（最多 3 轮 × 3s）。

```js
const want = files.map(f => f.name).sort();
let got = [];
for (let i = 0; i < 3; i++) {
  await page.waitForTimeout(3000);
  got = await wf.evaluate(() => Array.from(document.querySelectorAll('.fileTree-card-item'))
    .map(c => ((c.querySelector('.tool-tip-text-show-content') || {}).innerText || '').trim())
    .filter(Boolean).sort());
  if (want.every(n => got.includes(n))) break;
}
if (!want.every(n => got.includes(n))) return { err: 'upload-incomplete', want, got };
```

同理，票据本体上传后要回读 `附件(N)` 或「票据明细」里的文件名，再关面板。

## 五、失败处置决策树（不许无条件重来）

```
失败
├─ 属于「态不对」（A1/A2/A3 不成立）
│   ├─ 多了一层弹窗 → 循环关 uf-close 直到 modals 回到预期（第 1 次就地修）
│   ├─ 单选掉了 → 按 checked 补齐（只补缺的，不要点已选的）
│   ├─ 票袋没选中 → 重新点左栏（先 scrollIntoView）
│   └─ 行不对 → 用金额重新定位
│   → 修完重跑同一动作（这是第 1 次重试）
├─ 属于「动作没生效」（点了没反应）
│   ├─ 先确认不是被 mask 拦截 → 读 .wui-modal-mask
│   ├─ 改用物理坐标点（按钮 boundingBox 中心）
│   → 第 2 次重试
└─ 第 3 次仍失败 → 停
    → 截图 + 回报「当前态 S? / 期望 X / 实际 Y / 已试过哪三种点法」
    → 请用户协助，禁止继续加脚本
```

**禁止的恢复动作：**

| 禁止 | 原因 |
|---|---|
| 关掉弹窗重开一行 | 重开 = 状态回到默认 = 再次踩同一个单选坑。本次 4 次超时里 3 次是这样复现的 |
| 删除账单重录 | 附件串行本来是「编辑 → 附件 → 删除外来文件」就能修，重录一次要重走类型选择 + 日期 + 币种 |
| 同一脚本原样重跑 | 起点已变，结果必然不同；`enum.js` 三次结果不一致就是证据 |
| 改坐标 / 改序号硬试 | 只是把同一个假设换个写法，不是修状态 |

## 六、重试预算：单目标 3 次，全行 8 次

| 粒度 | 上限 | 超限动作 |
|---|---|---|
| 单个动作（点下一步 / 选日期 / 选币种 / 上传） | **3 次** | 停，报告该动作的期望 vs 实际 |
| 单行录入 | **8 次脚本** | 停，保留现场截图，请用户接手 |
| 整批 | 出现 2 行触顶 | 停整批，先复盘共性问题，不要一行行硬啃 |

参照：本次「改币种」写了 9 个脚本（`cu1`→`cu9`），「删附件」写了 7 个（`del1`→`del7`），
全部超过预算 2~3 倍。**如果 3 次就停，这两个点本可以各省 40 秒以上。**

## 七、诊断与写操作必须分离

- **诊断脚本（只读）**：只允许 `querySelector` / `getBoundingClientRect` / `return`，
  **禁止** `click` / `dispatchEvent` / `fill` / `evaluate` 里的赋值。
- **写脚本**：一个脚本只做一件事（开面板 / 填字段 / 上传 / 保存），做完立刻回读关键字段并 `return`。

本次 `t5.js`、`tp.js` 名为"诊断"，内部却在 `dispatchEvent('click')`，
结果 `before` / `after` 都是它自己改的，反而说不清是谁动了状态。

只读模板（可直接抄）：

```js
const wf = page.frames().find(f => f.url().includes('c4.yonyoucloud.com'));
const st = await wf.evaluate(() => {
  const ms = Array.from(document.querySelectorAll('.wui-modal')).filter(e => e.offsetWidth > 0);
  const top = ms[ms.length - 1];
  return {
    modals: ms.length,
    head: top ? (top.innerText || '').replace(/\n+/g, ' | ').slice(0, 200) : null,
    hasNmny: !!document.querySelector('[fieldid="znbzbx_tallydata|nmny"]'),
    hasOpenDate: !!document.querySelector('[fieldid="znbzbx_tallydata|dopendate_input"]'),
    fileInputs: Array.from(document.querySelectorAll('input[type=file]')).map(e => ({ multiple: e.multiple })),
    checked: Array.from(document.querySelectorAll('input[type=radio]')).filter(r => r.checked)
      .map(r => ((r.closest('label') || {}).innerText || '').trim().split('\n')[0])
  };
});
return st;
```

**输出只回传必要字段**：整页 `innerText` 会让回执被截断成 resource，反而看不到关键值。

## 八、单选的两个反直觉行为

1. **点已选中的 radio 会取消选中。** `wui-radio` 把 label 的 click 当 toggle。
   所以补选前必须先读 `checked`，只点缺的那个：

   ```js
   const need = ['手录行程', '补助'];
   for (const nm of need) {
     const done = await wf.evaluate((n) => {
       const ms = Array.from(document.querySelectorAll('.wui-modal')).filter(e => e.offsetWidth > 0);
       const top = ms[ms.length - 1];
       const r = Array.from(top.querySelectorAll('input[type=radio]'))
         .find(x => ((x.closest('label') || {}).innerText || '').trim().split('\n')[0] === n);
       return !!(r && r.checked);
     }, nm);
     if (!done) {
       // 用物理点击 label 中心，不要 dispatchEvent
       const b = await wf.evaluate((n) => {
         const ms = Array.from(document.querySelectorAll('.wui-modal')).filter(e => e.offsetWidth > 0);
         const top = ms[ms.length - 1];
         const r = Array.from(top.querySelectorAll('input[type=radio]'))
           .find(x => ((x.closest('label') || {}).innerText || '').trim().split('\n')[0] === n);
         const el = r.closest('label') || r;
         const q = el.getBoundingClientRect();
         return { x: Math.round(q.x + q.width / 2), y: Math.round(q.y + q.height / 2) };
       }, nm);
       await page.mouse.click(b.x, b.y);
       await page.waitForTimeout(600);
     }
   }
   // 校验：checked 必须同时包含两项
   ```

2. **「手录行程」是补助行的默认项。** 补助 = 账单类型「补助」+ 发票类型「手录行程」，
   两项分属两个单选组。只选「补助」就点下一步 → 校验失败 → 停在 S1。

## 九、断点恢复：先读现场，再决定从哪行开始

`.pool-progress.json` 只记录"我做到哪"，**不记录"平台实际到哪"**。恢复时必须先读后者：

1. 进票袋，读账单行数与每行金额；
2. 与计划 JSON 的 `rows[].hkd_amount` 逐项比对，**按金额认领已存在的行**（行序会被删改打乱）；
3. 差集才是待录行；
4. 对已有行逐行核对 `附件(N)`，与计划里的 `attachments.length` 比对，不等就地补；
5. 再开始录新行。

不做这一步直接续录，会产生重复行（本次删除重录就是因为没先认领已有行）。

## 十、一句话记账

每完成一行，记录三件事，出错时能立刻定位是哪一步开始偏的：

```
seq | 行金额 | 态迁移成功序列 | 附件回读 | 脚本调用次数
```

`脚本调用次数` 是健康指标：**单行超过 8 次说明流程有问题，不是页面慢。**
