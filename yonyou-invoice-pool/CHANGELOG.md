# 版本更新记录

本 skill 的所有变更都记在这里。版本号遵循 **语义化版本（MAJOR.MINOR.PATCH）**：
修文档/勘误 → PATCH；新增能力或规则 → MINOR；工作流或职责边界变更 → MAJOR。

## [0.2.0] — 2026-09-06　现场核实入口，修正与实测矛盾的旧流程

这一版做了一次完整的浏览器实测（微众科技租户，用友标签页现场连线），
把 0.1.0 里从报销单侧推测出来的流程逐条对照真实界面校正。

### 修正（Corrected）

**这三处是 0.1.0 写错了、照做必踩的，务必用新版：**

| # | 0.1.0 的写法（错） | 0.2.0 实测（对） |
|---|---|---|
| 1 | 新建票袋 = 弹窗输入名称 → 点「确定」 | **没有弹窗**。点侧栏「账单」下「+ 新增」（`div.add`）后，侧栏**内联生成**「票袋N」并立刻进入行内编辑，改名后回车/失焦落库 |
| 2 | 票袋内点「添加账单」录入 | 票袋视图**没有「添加账单」按钮**（那是报销单内的叫法）。入口是工具栏「**发票采集 ▼**」→「手工录入」 |
| 3 | 空票袋在「请选择账单」对话框里删 | 在**左侧栏选中该票袋** → 右侧工具栏「**更多**」→「**删除**」 |

### 新增（Added）

- **入口路径确认**：首页 → 快捷应用区第 1 个磁贴「**发票池（含收据）**」→ 默认落在「待报销」tab。
  写进了手册「环境备注」表，标记为已验证，以后不用再走「入口发现」。
- **新建票袋的可执行代码片段**：从触发新建、定位新生成的 `<input value="票袋N">`、
  改名到回读校验，完整一段 JS。
- **两条易错点说明**：
  - 新建时不要等 `.wui-modal`、不要点「确定」，等下去只会超时；
  - 校验改名结果要读 input 的 `value`，**别看侧栏文本**——input 宽约 78px，
    超过 ~6 个汉字会截断显示成「0720-0806吉…」，但**值是完整的**，看文本会误判成失败。
- **`安装说明.md`**：给同事分发用。含安装命令（macOS / Windows 双版）、依赖、
  发票目录规范、调用话术、两条最贵的坑、换租户时的入口适配方法。
- **本文件**：版本更新记录。

### 变更（Changed）

- `SKILL.md` 的「工作流」第 3、4 步改写为实测流程；
  「已知环境备注」从「尚未现场复核」改为「2026-09-06 已验证」。
- 手册头部「最近更新」改为 2026-09-06，正文第 2、3 节整体重写。
- `复核与交付.md` 第四节补「空票袋清理」小节，并注明顶层「更多」删不掉票袋。

### 打包修复（Packaging）

- 0.1.0 用 macOS `/usr/bin/zip` 打包，**中文文件名全部退化成 `????.md`**（不写 UTF-8 标志位），

- 0.2.0 改用 Python `zipfile` + `flag_bits |= 0x800` 打包，已实测解压后文件名完整无乱码。

## [0.3.0] — 2026-10-04　全量实跑一整袋，补录入侧的四条实测硬规矩

这一版不是在浏览器里"点几下看看"，而是**用 skill 完整录完了一个真实票袋**——
`0920-0930吉隆坡出差(HKD14195)`，8 行 / HK$14,195.17 / 29 份附件，
平台小计与归档清单勾稽一致。录入过程中踩到的坑全部回写进手册与脚本。

### 修正（Corrected）

| # | 0.2.0 的写法（有坑） | 0.3.0 实测（对） |
|---|---|---|
| 1 | 消费类型推断表里「用车 / 专车 / 打车」→ **其他交通** | 携程用车、滴滴 → **网约车**；只有 **Grab / 出租车** 才是其他交通。已按用户口径改脚本 `CONSUME_RULES` 与推断表 |
| 2 | 台账识别只认文件名含「台账 / 核验 / ledger」 | 实测 0920~0930 的台账叫「**归档清单.md**」，旧规则**整份漏检**，四项人工字段只能手读。现补「清单/归档/汇总/明细/报销材料」弱匹配，列为 ⚠️ 候选待人工确认 |
| 3 | 字段定位按 label 爬层、坐标兜底 | 一律用 **`fieldid`**（`znbzbx_tallydata\|nmny` 等）。坐标法会标到隐藏的 `\|id` 元素，报 `click: element is not visible` 超时 |

### 新增（Added）

- **消费类型全量清单**（实测枚举，写进手册第 3 节）：
  飞机 / 住宿（境内/境外）/ 网约车 / 其他交通 / 补助 / 服务类 / 有形/无形资产或其他。
- **`fieldid` 字段对照表**：金额 `\|nmny`、备注 `\|vmemo`、发生地 `\|vdef1`、
  币种 `\|vcurrency_name`、开票日期 `\|dopendate_input`、发生日期 `\|dcostdate_input`。
  手录行程**没有** `vdef1`（无发生地字段），别去找。
- **日历会记住上次月份视图**的坑与正确做法：每次打开日历先读 `.wui-picker-month-btn`
  校验月份，按差值决定翻几次，**禁止写死翻页次数**。
  （实测写死「prev×2」把 2026-09-20 填成了 2026-08-20，只能二次修正。）
- **两个单选都会静默点不动**：账单类型 + 消费类型必须各回读一次 `checked`，都确认后再下一步。
- **币种输入要先清空**：手录行程默认美元，直接输入会拼成「美元港币」；
  先 `fill('')` 再 `pressSequentially('港币')`，选完回读 `inputValue()`。
- **回归基线表**（写进 `SKILL.md` 环境备注）：0720-0806（6 行 / HK$23,921.47）、
  0920-0930（8 行 / HK$14,195.17），改脚本后必须重跑这两个目录做回归。

## [0.1.0] — 2026-09-05　初版

从一份示例报销单的实操实录中复盘提炼而成。

### 背景

前一轮是**借道报销单填发票池**：在差旅费报销单的「发票池（含收据）→ 添加账单」里
逐行手工录入 6 张账单（合计 HK$23,921.47），录完再整批勾选拉进报销单。
这条路能走通，但有三个结构性问题：

1. 行多时无法断点续录，中断就得从头来；
2. 报销单侧「**保存为草稿**」≠「保存」，误点一次数据就脱离正式单据，列表页搜不到（**已踩**）；
3. 票袋没有被显式创建，账单散在默认容器里，不可复用、难整袋核对。

于是把录入动作从报销单里剥离出来，做成独立票袋 skill。

### 初版内容

- `SKILL.md`：职责边界（只做票袋，不碰报销单表头 / 不关联 TAPL / 不提交）、
  5 步工作流、7 条硬性原则（两步式确认、原始文件只读、只点保存、字段不臆测、
  失败即停、票据本体唯一、不越界）。
- `references/平台操作手册.md`：iframe 接入、入口发现流程、字段定位 helper、
  日历面板残留坑、币种联想、文件上传 JS 注入、断点续录。
- `references/目录解析与字段口径.md`：目录约定、消费类型推断表、
  可推导 vs 必人工字段（日期 / 发生地 / 备注一律标 TODO）。
- `references/复核与交付.md`：逐行校验、收尾复核清单、单页 HTML 报告规格。
- `scripts/scan_invoice_dir.py`：目录 → 录入计划（Markdown + JSON）。
  实测 0720-0806 目录：6 行 / HK$23,921.47 / 20 份附件，类型、原币、汇率全部识别正确。

### 已知限制

- 「发票池（含收据）」在首页的入口位置**未现场复核**，要求首次运行走「入口发现」枚举候选
  并让用户确认 → 已在 0.2.0 解决。
- 新建票袋、票袋内录入入口均为**推测**，与实测有出入 → 已在 0.2.0 修正。
