# 版本更新记录

本 skill 的所有变更都记在这里。版本号遵循 **语义化版本（MAJOR.MINOR.PATCH）**：
修文档/勘误 → PATCH；新增能力或规则 → MINOR；工作流或职责边界变更 → MAJOR。

## [0.3.2] — 2026-10-23　把「出错就打转」写死成纪律：状态断言与收敛协议

这一版**没有加新功能**，只修一件事：**出错之后无限重试。**

起因是 0.3.1 实跑结束后的一次复盘——把一份脱敏票袋会话的脚本调用逐条还原，
发现 **22 分 35 秒里打了 106 个脚本，真正推进业务动作的只有约 9 个（8.5%），
64% 花在"定位当前在哪 + 纠上一次的错"**。最密的 55 秒里写了 9 个脚本只为改一个币种。

根因不是平台不稳定，是**动作没有前置断言**，且失败后的恢复动作（关弹窗重开、删账单重录）
会把页面推回**出问题的那个起点**，于是同一个错误被反复复现。

### 新增（Added）

- **`references/状态断言与收敛.md`**（新文件，第 4 步开工前必读）：
  - 四态状态机（`S0` 列表 / `S1` 类型选择 / `S2` 明细表单 / `S3` 附件面板）与合法迁移；
  - **动作前三断言**：`modal` 层数、`.ticketBag-item.select` 名称、目标行金额 / `附件(N)`；
  - 定位器规范：列表行按金额找 `tr`（禁固定 y 坐标）、file input 取最上层那个（禁取第一个）、
    按钮文本精确匹配并限定最上层 modal；
  - 上传完成判据：回读 `.fileTree-card-item` 文件名清单与期望逐项比对（最多 3 轮 × 3s），
    不许只用 `waitForTimeout` 就认为成功；
  - 失败处置决策树 + 禁止清单 + 重试预算（单动作 3 次 / 单行 8 个脚本）；
  - 诊断脚本与写脚本分离（只读模板可直接抄）；
  - 断点恢复：先按金额认领平台已有行，再做差集，防重复录入。

### 变更（Changed）

- `SKILL.md` 第 4 步开头加「开工前必读」与三断言表；新增第 10~12 条收敛规矩
  （禁坐标定位、file input 取最上层、失败不许重开弹窗）；
- `scripts/scan_invoice_dir.py` 与字段口径同步兼容 `invoice-organizer` v2.3.0：补助逐日台账 txt 识别为票据本体，不再误判成说明文件；
- 硬性原则「失败即停」细化为**带预算的失败即停**：明确禁止「关弹窗重开 / 删账单重录 / 原样重跑同一脚本」；
- 「附件挂错行的修法」补成因说明（取到残留面板的 input）并指向新文件 3.2 / 4 节；
- 规则文件表加入新条目；
- 版本号 `0.3.1` → `0.3.2`。

### 不改的东西

- 消费类型口径、币种处理、日历翻页、附件面板路径均无变化；目录扫描器仅增加补助逐日台账 txt 的票据本体兼容。
- 回归基线不变（共三份脱敏票袋样例）。

## [0.3.1] — 2026-10-23　第三袋实跑：票袋命名、附件串行与未分组票袋

0.3.0 之后又完整跑完一份脱敏票袋（6 行 / 16 份附件），
全程用脚本驱动浏览器，暴露了 0.3.0 没覆盖的六个坑，全部回写。

### 修正（Corrected）

| # | 0.3.0 的写法（会踩） | 0.3.1 实测（对） |
|---|---|---|
| 1 | 票袋名照搬用户的 `日期范围-城市-用途(HKD金额)` | 平台红条拒绝：「**票袋名称只能包括中英文字和数字**」。连字符、括号、空格、下划线都不行，改 `日期范围城市用途HKD金额` |
| 2 | 表单失焦点 body 空白处 | 点空白 = **关闭票据明细弹窗**，未保存字段全丢。用 `Tab` 键失焦 |
| 3 | 按 `[data-tb-form]` 作用域找 `input[type=file]` | file input 挂在 `wui-modal-body-overflow` 层，**必须全局** `document.querySelectorAll('input[type=file]')` |
| 4 | 用 `/^附件\(\d+\)$/` 找附件按钮 | 0 份附件时按钮文字就是「**附件**」，没有 `(0)`。用 `/^附件/` 兜底 |
| 5 | 保存完就认为进了目标票袋 | 左栏未真正选中时，账单会落进「未分组票袋」甚至「票袋5」。保存后必须核对左栏 `.ticketBag-item.select` 与票袋计数 |
| 6 | 附件删改走「详情态附件面板」 | 详情态面板只有「下载 / 文件名排序」，**没有删除**；必须先点「编辑」，编辑态才出现「删除」 |

### 新增（Added）

- **附件串行（串行挂到上一行）的修法**：症状是某行 `附件(11)` 里混着别行文件、另几行 0 份。
  不用删账单重录——「编辑 → 附件 → 白名单勾掉外来文件 → 删除 → 确认『是否删除选中的【N】个文件』→ 关闭 → 保存」，
  再对缺附件行「编辑 → 附件 → 注入 `input[multiple]` → 回读 `附件(N)` → 保存」。
- **未分组票袋的搬运法**：勾选行 →「移动」→ 弹窗「选择移动到」点目标票袋 →「移动」。
- **侧栏票袋超过一屏时的定位法**：先 `scrollIntoView({block:'center'})` 再算 `getBoundingClientRect()` 点击；
  直接点会落在 iframe 可视区外，票袋不切换。
- **残留遮罩的处理**：`wui-modal-mask` 会拦截所有点击（Playwright 报 `intercepts pointer events`），
  循环取最上层 modal 的 `.uf-close` 三连 MouseEvent 点掉；`Escape` 无效。
- **Tabbit 脚本形态**：`nodejs` 的 stdin 代码必须写成**语句体**（`const wf = ...; return {...}`），
  `module.exports = async ({page}) => {}` 会被当表达式求值，`value` 恒为 `null`；
  `page.bringToFront()` 在该实例报 `foregroundPolicy=preserve`，不要调。
- **回归基线**新增第三份脱敏票袋：6 行 / 16 份附件；附件分布已完成逐行核验。

### 变更（Changed）

- `SKILL.md` 第 4 步的「四条硬规矩」扩为「九条」，并新增「附件挂错行的修法」小段；
- 「已知环境备注」补三条环境坑（侧栏滚动、遮罩拦截、Tabbit 脚本形态），回归基线表加第三行；
- 版本号 `0.3.0` → `0.3.1`。

## [0.3.0] — 2026-10-04　全量实跑一整袋，补录入侧的四条实测硬规矩

这一版不是在浏览器里"点几下看看"，而是**用 skill 完整录完了一个真实票袋**——
`0920-0930吉隆坡出差(HKD14195)`，8 行 / HK$14,195.17 / 29 份附件，

### 修正（Corrected）

| # | 0.2.0 的写法（有坑） | 0.3.0 实测（对） |
|---|---|---|
| 1 | 消费类型推断表里「用车 / 专车 / 打车」→ **其他交通** | 携程用车、滴滴 → **网约车**；只有 **Grab / 出租车** 才是其他交通。已按用户口径改脚本 `CONSUME_RULES` 与推断表 |

### 新增（Added）

- **消费类型全量清单**（实测枚举，写进手册第 3 节）：
  飞机 / 住宿（境内/境外）/ 网约车 / 其他交通 / 补助 / 服务类 / 有形/无形资产或其他。
- **`fieldid` 字段对照表**：金额 `\|nmny`、备注 `\|vmemo`、发生地 `\|vdef1`、
  币种 `\|vcurrency_name`、开票日期 `\|dopendate_input`、发生日期 `\|dcostdate_input`。
  手录行程**没有** `vdef1`（无发生地字段），别去找。

- **币种输入要先清空**：手录行程默认美元，直接输入会拼成「美元港币」；

## [0.1.0] — 2026-09-05　初版

从一份脱敏示例报销单的实操实录中复盘提炼而成。

### 背景

前一轮是**借道报销单填发票池**：在差旅费报销单的「发票池（含收据）→ 添加账单」里
逐行手工录入 6 张账单（合计 HK$23,921.47），录完再整批勾选拉进报销单。
这条路能走通，但有三个结构性问题：

1. 行多时无法断点续录，中断就得从头来；
2. 报销单侧「**保存为草稿**」≠「保存」，误点一次数据就脱离正式单据，列表页搜不到（**已踩**）；
3. 票袋没有被显式创建，账单散在默认容器里，不可复用、难整袋核对。

于是把录入动作从报销单里剥离出来，做成独立票袋 skill。

### 初版内容

- `SKILL.md`：职责边界（只做票袋，不碰报销单表头 / 不关联 TAPL / 不提交）、
  5 步工作流、7 条硬性原则（两步式确认、原始文件只读、只点保存、字段不臆测、
  失败即停、票据本体唯一、不越界）。
- `references/平台操作手册.md`：iframe 接入、入口发现流程、字段定位 helper、
  日历面板残留坑、币种联想、文件上传 JS 注入、断点续录。
- `references/目录解析与字段口径.md`：目录约定、消费类型推断表、
  可推导 vs 必人工字段（日期 / 发生地 / 备注一律标 TODO）。
- `references/复核与交付.md`：逐行校验、收尾复核清单、单页 HTML 报告规格。
- `scripts/scan_invoice_dir.py`：目录 → 录入计划（Markdown + JSON）。
  实测 0720-0806 目录：6 行 / HK$23,921.47 / 20 份附件，类型、原币、汇率全部识别正确。

### 已知限制

- 「发票池（含收据）」在首页的入口位置**未现场复核**，要求首次运行走「入口发现」枚举候选
  并让用户确认 → 已在 0.2.0 解决。
- 新建票袋、票袋内录入入口均为**推测**，与实测有出入 → 已在 0.2.0 修正。
