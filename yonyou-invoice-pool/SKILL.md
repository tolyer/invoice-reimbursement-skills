# 用友发票池票袋填写

## 一句话职责

**只做一件事**：把一个结构化发票目录，完整、准确地搬进用友发票池里**一个**新建票袋。
不碰报销单表头、不关联事项申请、不提交。录完交付台账 + 单页 HTML 报告。

## 与相邻 skill 的边界

| 场景 | 用哪个 |
|---|---|
| 原始凭证还是散装文件，需要识别/勾稽/归档命名 | `invoice-organizer`（先把目录整理成标准结构） |
| 目录已结构化，要录进**发票池票袋** | **本 skill** |
| 票袋已建好，要填**报销单**并提交 | `invoice-organizer` 的 `references/报销单填写逻辑.md` |

启动时先说清自己只做票袋，如果用户要的是报销单，明说超出范围并转交。

## 工作流

### 第 0 步：声明范围 + 前置检查

向用户确认四件事（缺哪个问哪个，别猜）：

1. **发票目录路径**——必须是 `NN-描述-HKD金额/` + `★票据本体/` + `☆附件/` 结构；
   不是这个结构就先转 `invoice-organizer`，不硬上。
2. **票袋名称**——没给就按 `<行程区间><城市><用途>` 建议一个（如 `0720至0806吉隆坡差旅`），让用户确认；名称只使用中文、英文字母和数字。
3. **浏览器是否已打开用友并登录**——用友在 Tabbit 的哪个任务名/分组下（如 `--task TERD-fill --group TERD-fill`）。
4. **台账位置**（可选）——有台账就优先从台账取日期/发生地/备注，准确性远高于重新推导。

### 第 1 步：解析目录 → 生成《票袋录入计划》

```bash
python3 \
  ~/.workbuddy/skills/yonyou-invoice-pool/scripts/scan_invoice_dir.py \
  "<发票目录>" --out 票袋录入计划.md --json 票袋录入计划.json
```

脚本自动给出：逐行清单（账单类型 / 消费类型 / HKD 金额 / 原币 / 汇率）、文件上传清单、待确认缺口。

若检出台账（md/xlsx），**优先读台账**补齐四项人工字段：
开票日期 / 发生日期 / 发生地 / 备注。台账口径与脚本推导冲突时以台账为准。

### 第 2 步：⚠️ 用户确认后才动浏览器

把《票袋录入计划》完整呈现给用户，重点标出：

- 推断出的消费类型（猜错的要改）；
- 四项 TODO 字段的取值来源；
- 数据缺口（缺票据本体、缺汇率凭证、票据本体多于 1 个等）。

**未得到明确确认，不做任何平台操作。** 这是硬性的两步式节奏。

### 第 3 步：新建票袋

首页 → 快捷应用区第 1 个磁贴「**发票池（含收据）**」（2026-09-06 已验证）→ 默认落在「待报销」tab
→ 左侧栏「账单」下「**+ 新增**」（`div.add`）→ 侧栏**内联**生成「票袋N」→ **行内改名** → 回车落库。

⚠️ 这里**没有弹窗**：不要等 `.wui-modal`、不要点「确定」，直接对生成的 `<input value="票袋N">` 改名。
校验时读 input 的 `value`，别看侧栏文本（窄，长名会截断显示，但值是完整的）。

若换租户/版本导致入口对不上，按 `references/平台操作手册.md` 第 1 节的「入口发现」枚举候选再确认，
并把结论写回手册的「环境备注」表。

建完回读列表，确认票袋出现且名称无误。

### 第 4 步：逐行录入

> **开工前先读 `references/状态断言与收敛.md`。** 这一步的失败模式不是"报错"，是"打转"——
> 2026-10-23 实测 22 分钟打了 106 个脚本，真正推进业务的只有 9 个（8.5%）。
> 那份文件里的三断言、定位器规范、失败处置决策树、3 次重试预算都是硬约束。

先在左侧栏**点选票袋**进入票袋视图，再每行走：
工具栏「**发票采集 ▼**」→「手工录入」→ 选账单类型 → 选消费类型
（**回读 checked 校验**）→ 下一步 → 填字段 → 上传票据本体 → 上传附件 → 关闭附件面板 → **保存**。

⚠️ 票袋视图**没有「添加账单」按钮**（那是报销单内的叫法），入口就是「发票采集 ▼」。

**页面只有四个态，动作前先判态**（`S0` 列表 / `S1` 类型选择 / `S2` 明细表单 / `S3` 附件面板）。
每发一个写操作前跑三条断言，任一不成立就**就地修态**，不往下走：

| # | 断言 | 不满足时 |
|---|---|---|
| A1 | `.wui-modal` 可见层数 === 预期 | 多了循环关 `uf-close`，少了回 `S0` 重开 |
| A2 | `.ticketBag-item.select` 文本 === 目标票袋 | 重新点左栏（先 `scrollIntoView`） |
| A3 | 目标行金额 / `附件(N)` === 期望 | 按金额重新定位行，**禁止按坐标** |

四条 2026-10-04 实测、每次都会遇到的硬规矩（详见手册第 3~4 节）：

1. **字段定位一律用 `fieldid`**：输入框带 `fieldid="znbzbx_tallydata|xxx"`——
   金额 `|nmny`、备注 `|vmemo`、发生地 `|vdef1`、币种 `|vcurrency_name`、
   开票日期 `|dopendate_input`、发生日期 `|dcostdate_input`。
   别用 label 爬层，更别用坐标（坐标会标到隐藏的 `|id` 导致「element is not visible」超时）。
2. **两个单选都可能静默点不动**：账单类型和消费类型**各回读一次 checked**，都确认了再点下一步，
   否则弹「请选择发票类型」红条。
3. **日历会记住上一次的月份视图**：每次打开日历**先读 `.wui-picker-month-btn` 校验月份**，
   按差值决定翻几次，**绝不写死「翻 N 次」**（写死过一次，把 09-20 填成了 08-20）。
4. **币种先 `fill('')` 再输入**：手录行程默认美元，直接输入「港币」会拼成「美元港币」。
   输入后靠联想选 HKD，回读 inputValue 期望「港币」。

五条 2026-10-23 实测补充（0.3.1，每条都真实踩过）：

5. **票袋名只允许中文 + 英文字母 + 数字**：`日期范围-城市-用途(HKD金额)` 会被红条拒绝
   （「票袋名称只能包括中英文字和数字」）。连字符、括号、空格、下划线一律不要；
   改用 `日期范围城市用途HKD金额` 这类写法。
6. **失焦绝对不要点页面空白**：点 body 空白处等于「关闭」`票据明细` 弹窗，未保存的字段全丢。
   要失焦就按 `Tab` 键，或点表单自身的标题区域。
7. **附件 file input 不在表单容器里**：挂在 `wui-modal-body-overflow` 层，
   必须全局 `document.querySelectorAll('input[type=file]')` 找 `[multiple]` 那个，
   按 `[data-tb-form]` 作用域查会得到 0 个。
8. **附件数为 0 时按钮文字是「附件」不是「附件(0)」**：按 `/^附件\(\d+\)$/` 匹配会漏掉空附件行，
   用 `/^附件/` 兜底。
9. **保存后要核对行是否落进目标票袋**：左栏未真正选中时，保存的账单会进「未分组票袋」甚至「票袋5」。
   进票袋后先确认 `.ticketBag-item.select` 的名称，再点「发票采集」；
   已经落错的用「勾选行 → 移动 → 选目标票袋 → 移动」搬回来。

三条 2026-10-23 复盘出的收敛规矩（0.3.2，**这一版的重点**）：

10. **列表行只能用业务身份定位**：`page.mouse.click(520, 固定y)` 在表格滚动 / 删行 / 弹窗遮挡后
    指向的是另一行。按金额匹配到 `tr` 再取它自己的 boundingBox，取不到就返回 `row-not-found` 并停。
11. **附件 file input 要取最上层那个**：`find(e => e.multiple)` 取第一个会把文件传到上一行
    （实测住宿行被塞进 11 份、接机与 Grab 各 0 份）。取 `[multiple]` 里 `closest('.wui-modal')`
    可见的最后一个；上传后**回读文件名清单**与期望逐项比对，不能只 `waitForTimeout` 就认为成功。
12. **失败后不许"关弹窗重开"**：重开 = 状态回到默认 = 再次踩同一个单选坑。
    只允许就地修（关多余弹窗 / 按 `checked` 补单选 / 重新点票袋 / 按金额重新定位行）。
    单动作 3 次、单行 8 次为上限，超限停下报告「当前态 + 期望 vs 实际」。

逐行校验见 `references/复核与交付.md` 第一节，不符当场补做。

**附件挂错行的修法（0.3.1，勿删账单重录）**：附件偶尔会整批挂到上一行（症状：某行 `附件(11)` 里混着别行的文件，
另几行是 0 份）。**成因是取到了残留面板的 `input[multiple]`**，注入前按新文件 3.2 节取最上层那个，
注入后按 4 节回读文件名清单。修法不是删账单重录，而是：

1. 点该行 →「编辑」→ 点「附件」按钮 → 面板才出现「**删除**」（详情态的附件面板只有下载/排序，**没有删除**）；
2. 按文件名白名单勾掉外来文件（面板底部会显示「已选 N/M」），点「删除」→ 确认「是否删除选中的【N】个文件」；
3. 关闭面板 →「保存」；
4. 对缺附件的行重复：编辑 → 附件 → 注入 `input[multiple]` → 回读「附件(N)」→ 关闭 → 保存。

每完成一行，把 `seq` 写进 `<工作目录>/.pool-progress.json`，
中断后从第一个未完成行继续，并在恢复前先读票袋已有账单列表防重。

### 第 5 步：收尾复核 + 交付

复核清单见 `references/复核与交付.md` 第二节。交付：
逐行明细台账（Markdown）+ 单页 HTML 报告，用 `present_files` 打开。
结尾固定附上「如何从票袋拉进报销单」的提示语（见该文件第四节）。

## 硬性原则

- **两步式确认**：先出《票袋录入计划》→ 用户确认 → 才动浏览器；未确认不点任何按钮。
- **原始文件只读**：上传用文件先 `cp` 到 `/tmp` 短路径再传，**绝不移动 / 重命名 / 删除**源目录文件。
- **只点「保存」，绝不点「保存为草稿」**：草稿只进草稿箱，不落票袋，列表页搜不到，等于白干。
- **日期 / 发生地 / 备注不臆测**：目录推不出来就必须从台账取或问用户，宁可多问一次。
- **失败即停，且有预算**：单动作连续失败 3 次、单行超过 8 个脚本 → 停止，截图 + 说明「当前态 / 期望 / 实际 / 已试过什么」+ 请求用户协助。
  恢复动作只允许**就地修态**（关多余弹窗、按 `checked` 补单选、重选票袋、按金额重定位行），
  **禁止关掉弹窗重开、禁止删账单重录、禁止原样重跑同一脚本**——这三件事都会把状态推回故障起点。
- **票据本体唯一**：平台每行只收 1 张票据本体，`★票据本体/` 里多于 1 个必须先让用户裁决。
- **不越界**：不填报销单表头、不关联 TAPL、不点击任何「提交」。

## 已知环境备注（微众科技租户，2026-09-06 建袋流程 / 2026-10-04、2026-10-23 录入流程 已验证）

- 平台 iframe 域：`c4.yonyoucloud.com`；主文档标题「微众科技」且 body 为空，控件全在 iframe 里。
- UI 组件前缀 `.wui-`；弹窗 `.wui-modal`；日历单元格 `td.wui-picker-cell-in-view`。
- 入口路径：**首页 → 快捷应用区第 1 个磁贴「发票池（含收据）」**。进站默认在「待报销」tab。
- 票袋列表在左侧栏（票袋 = 发票池内的分组袋）。新建票袋：点侧栏「账单」下的 **「+ 新增」**（`div.add`），
  **直接在侧栏内联生成** `票袋N`，名字立刻可改。**不是弹窗**。
- 进入票袋后，工具栏有「发票采集 ▼ | 生成报销单 | 移动 | 转交 | 批改 | 更多」，
  录入账单的入口是工具栏「**发票采集 ▼**」→「手工录入」/ 扫码 / 邮箱导入（与报销单内同一套）。
- Playwright `setInputFiles()` 在此环境**会挂起**，一律改用 JS 注入（见手册第 5 节）。
- 文件上传单帧 base64 上限约 1.25MB，超限需分片。
- 消费类型口径：携程用车 / 滴滴 → **网约车**；Grab → **其他交通**；补助 → 手录行程 + 补助（无发生地字段）。
- **侧栏票袋数超过一屏时**：先 `el.scrollIntoView({block:'center'})` 再点；
  直接点会落在可视区外（点击位置 y > iframe 高度，事件打到别处，票袋不会切换）。
- **残留的 `.wui-modal` / `.wui-modal-mask` 会拦截所有点击**（Playwright 报
  `wui-modal-mask ... intercepts pointer events`）：循环取最上层 modal 的 `.uf-close` 用 MouseEvent 三连点掉，
  `Escape` 无效。
- **Tabbit `nodejs` 脚本必须是语句体**：直接写 `const wf = page.frames()...; return {...}`，
  不能用 `module.exports = async ({page}) => {}`（会被当表达式求值，`value` 恒为 `null`）。
  另外 `page.bringToFront()` 在该实例会报 `foregroundPolicy=preserve`，别调。
