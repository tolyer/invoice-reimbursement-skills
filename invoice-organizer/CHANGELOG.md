## 版本号怎么定

| 变更类型 | 改动哪一位 | 例子 |
|---|---|---|
| 文案修订、错别字、表格格式、局部纠错 | **修订号**（1.2.0 → 1.2.1） | 修正某个汇率数值笔误 |
| 新增规则条目、新增文件（如新的 README）、补充判定分支 | **次版本号**（1.2.0 → 1.3.0） | 新增一种凭证类型、新增 README |
| 工作流结构性调整、步骤增删、归档方式变化 | **主版本号**（1.2.0 → 2.0.0） | 把「确认后才归档」改成「边核验边归档」 |

> 每次改动请同步：① 本文件新增一条；② `SKILL.md` frontmatter 的 `version` 字段；③ 被改动的 `references/*.md` 顶部「最近更新」日期。

## v1.3.0 · 2026-09-07

**变更类型**：次版本更新（补助规则重算 + 新增文件）

**改了什么**

补助天数由「按自然日」改为**按工作日计算**：

| 日期 | 新规则 |
|---|---|
| 出发当天 | 0.5 天（逢周末计 0） |
| 中间的工作日 | 每天 1 天，**周六周日一律剔除** |
| 落地当天 | 0.5 天（逢周末计 0） |
| 法定节假日 | 暂不自动扣减，但**在台账表格内打 ⚠️ 列出具体日期，请用户二次确认** |

同时新增两个配套文件：

- `references/节假日日历.md` — 2026 年官方放假安排（国办发明电〔2025〕7 号）+ 调休上班日；含机器可读 DATA 区块，每年 11 月更新
- `scripts/calc_subsidy.py` — 补助计算器，逐日展开输出明细 + 金额折算 + 节假日提醒，支持 `--rate` / `--fx` / `--deduct-holiday` / `--weekend-travel-day`

并提供两个可调开关（在 `账单分类与勾稽规则.md` 第四节）：`DEDUCT_HOLIDAY`（节假日是否自动扣，默认 false）、`WEEKEND_TRAVEL_DAY`（出发/落地日逢周末是否仍计半天，默认 false）。

**影响文件**

- `references/账单分类与勾稽规则.md` — 新增第四节「补助天数算法（只看工作日）」；原汇率节顺延为第五节
- `references/报销单填写逻辑.md` — 备注写法增加补助行口径示例（须注明剔除周末）
- `SKILL.md` — 硬性原则新增「补助只算工作日」；第 2 步新增补助天数校验与节假日提醒要求
- `README.md` — 新增 3.5 节；「停下来问你的事」增至五件

**⚠️ 对你的影响（重要）**

这是一次**金额级变更**。以 0720-0806 吉隆坡行程为例：

| 口径 | 天数 | USD | HKD（汇率 7.84） |
|---|---|---|---|
| 旧（含周末） | 17.0 天 | 1,275.00 | 9,996.00 |
| 新（仅工作日） | **13.0 天** | **975.00** | **7,644.00** |

差额来自 07-25、07-26、08-01、08-02 四个周末日。**如果你此前按旧口径生成过台账或提交过单据，需要重新核对补助金额。**

## v1.2.0 · 2026-09-06

**变更类型**：次版本更新（判定逻辑修订）

**改了什么**

专车不再默认并入飞机行，改为**按支付凭证勾稽结果判定**：

| 勾稽结果 | 判定 | 处理 |
|---|---|---|
| 支付截图金额 C = 机票 A + 专车 B | 同一携程订单 | 合并成一行 |
| C = A（专车另有独立支付） | 两个独立携程订单 | 飞机、专车分别成行 |

**影响文件**

- `references/账单分类与勾稽规则.md` — 第二节第 3 条重写为判定表；必备材料清单新增「专车（独立成行时）」一行
- `references/文件识别规则.md` — 专车小节新增⚠️判定式
- `references/报销单填写逻辑.md` — 新增「专车行的两种形态」（合并形态 / 独立形态）
- `README.md` — 新增 3.4 节；「停下来问你的事」由 3 件增至 4 件
- `SKILL.md` — 第 0 步受理范围第 3 类描述更新

**对你的影响**：无破坏性变更。上一版按「默认合并」处理的单据，只要满足 `C = A + B`，结论完全一致；只有**专车与机票分开支付**的情况才会拆成两行。

## v1.0.1 · 2026-09-05

**变更类型**：修订（缺陷修复）

**修了什么**

修复**汇率截图凭假设归类币种对**的缺陷。

- **问题**：`SCR-20260904-skfe.png`（实为 Google「1 MYR = 1.93 HKD」）与 `SCR-20260904-sjyj.png`（实为中行牌价 CNY 0.8646）被互换归类，导致马币汇率截图错放进机票文件夹。
- **根因**：SCR 文件名的随机码不含任何币种信息，识别阶段未逐张打开视觉确认。
- **修复**：
  - `文件识别规则.md` — 汇率截图小节加⚠️强制流程：逐张视觉确认 → 建映射表 → 用户确认后才归档
  - `账单分类与勾稽规则.md` — 新增「汇率映射强制确认」规则
  - `SKILL.md` — 第 2 步核验报告必含汇率映射表确认项

**对你的影响**：**如果你在 2026-09-05 之前用过本 skill 归档过发票，请检查各行文件夹里的汇率截图是否放对**——数值虽然没错，但文件可能张冠李戴。

## v1.0.0 · 2026-09-05

**变更类型**：首个版本

**包含内容**

- 四条硬性原则：两步式确认、原始文件只读、数据自校验、汇率留痕

**基线校准**：2026-09-05，0720-0806 吉隆坡出差核销实践 + 上期单据 TERD2605270002 逐字段复读。
