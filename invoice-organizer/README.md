# 发票整理助手 · 使用说明

> 一套「先核验、后归档」的差旅报销凭证整理流程。
> 你给材料 → 我出核验台账 → 你确认 → 我才动手整理发票夹。
> **在你确认之前，我不会移动、重命名或删除你的任何原始文件。**

---

## 一、我只受理这 5 类凭证

| # | 类别 | 说明 |
|---|---|---|
| 1 | 携程飞机票 | 订单确认邮件、中英版行程单、支付截图 |
| 2 | 携程酒店 | 酒店水单、入住证明、支付截图（**每段订单单独一行**） |
| 3 | 携程专车 | 用车行程单（**看支付凭证决定**是否并入飞机行，见下方 3.4） |
| 4 | Grab 流水 | Grab Member Statement 对账单 + 逐笔台账 |
| 5 | 出差补助 | 手录行程，无票据本体，只需汇率截图 |

范围外的凭证（如签证费、餐饮发票、地铁票）请先告诉我，确认后再处理。

**币种规则**：消费币种可以是 MYR / CNY / HKD 等，但**报销货币一律 HKD**，**报销单计价货币为 USD**。每一条账单除了消费凭证，还必须附一张「消费币种 → HKD」的汇率截图。

## 二、开工前：先把材料放进一个文件夹

在某处建一个文件夹，建议用行程区间命名，例如：

```
/Users/你的用户名/Downloads/0720-0806/
```

把本期所有凭证丢进去就行，**不用预先改名、不用分类、不用删重复文件**——那是我后面要做的事。

然后你只需要把**文件夹路径**给我（不用逐个上传文件）：

> 帮我整理 `~/Downloads/0720-0806` 里的发票

## 三、首次上传：请按这份清单准备

### 3.1 消费凭证（按类别勾）

| 类别 | ★ 票据本体（缺了就没法核销） | ☆ 配套附件 |
|---|---|---|
| **飞机** | 携程订单确认邮件（QQ 邮箱打印的 PDF） | 支付截图（IMG_xxxx）、中英版机票行程单 |
| **酒店**（每段一行） | 酒店水单（文件名带订单尾号） | 入住证明（尾号须与水单一致）、支付截图 |
| **专车** | 用车行程单 | 支付截图（**靠它判断是合并还是单独成行**，见 3.4） |
| **Grab** | Grab Member Statement 对账单（含区间合计的 PDF） | — （逐笔台账我来生成 CSV） |
| **补助** | 无（手录行程） | 告诉我出发日、返回日、日标准（当前 75 USD/天）；**按工作日计算**，见下方 3.5 |

### 3.2 汇率截图（每行都要一张）

| 消费币种 | 汇率来源 | 截图内容 |
|---|---|---|
| CNY（人民币） | 中国银行外汇牌价 | 港币折算价，如 86.46 → 0.8646 |
| MYR（马币） | Google 汇率 | 「1 MYR = X HKD」 |
| USD（美元） | Google 汇率 | 「1 USD = X HKD」 |

> ⚠️ 截图文件名（如 `SCR-20260904-skfe.png`）里的随机码**不含币种信息**。
> 我会逐张打开确认内容，并把「文件名 ↔ 币种对 ↔ 数值」映射表列进台账请你核对——**这一步请务必看一眼**，历史上这里出过错。

### 3.3 常见的漏项（对照自查）

- [ ] 多段酒店：**每段订单**都要单独的水单 + 入住证明
- [ ] 支付截图金额要和订单/水单金额对得上
- [ ] 有往返机票的，行程单要包含两个航班
- [ ] Grab 对账单要覆盖完整出差区间

缺什么不用怕——直接把现有的给我，我会列出缺料清单告诉你补。

### 3.4 专车：合并成一行，还是单独成行？

**不默认合并，看支付凭证勾稽**（机票金额 A、专车金额 B、支付截图金额 C）：

| 勾稽结果 | 含义 | 我会怎么处理 |
|---|---|---|
| **C = A + B** | 一笔支付同时付了机票和专车 → 同一个携程订单 | **合并成一行**：金额 = A + B，票据本体是机票订单确认邮件，专车行程单作附件，备注注明「含 MMDD 携程专车送机」 |
| **C = A**（专车另有独立支付） | 两笔支付分开 → 两个独立携程订单 | **分别成行**：飞机一行、专车一行；专车行票据本体 = 用车行程单，两行各配自己的支付截图 |

> 所以**专车的支付截图一定要给我**，没有它我没法判断是合并还是拆分，只能停下来问你。

### 3.5 补助：按工作日算，怎么算的

**出差补助只计工作日**，具体是：

| 日期 | 天数 | 说明 |
|---|---|---|
| 出发当天 | **0.5 天** | 逢周末则不计（除非你让我改开关） |
| 中间的**工作日** | 每天 1 天 | **周六、周日一律不计** |
| 落地当天 | **0.5 天** | 同上 |
| 法定节假日 | 暂不自动扣 | **但我会标注出来请你确认**，见下 |

举例——7/20 周一出发、8/6 周四返回，日历上 18 天，但剔除 7/25、7/26、8/1、8/2 两个周末后：

```
0.5 + 工作日12天 + 0.5 = 13 天 × 75 USD = 975 USD
（旧口径含周末是 17 天 / 1,275 USD，差 300 美元）
```

**节假日怎么处理的**：我不替你决定扣不扣。如果出差区间里含有法定节假日，我会在**台账表格里打 ⚠️ 并列出具体日期**（如「2026-10-01 国庆」），请你确认是否计入——这条提醒会写在表格里，不是只在对话里说一句。区间没有节假日的话，台账里会注明「区间内无法定节假日」。

> 想改口径直接跟我说：比如「周末也要算」「节假日要扣掉」「出发日逢周末也算半天」，我改完规则下次就按新的走。

## 四、怎么给我指令（命令速查）

| 阶段 | 你这样说 | 我会做什么 |
|---|---|---|
| **① 开工** | 「帮我整理 `路径` 里的发票」 | 全量列出文件，逐份识别，出**初版核验台账** |

| **② 改口径** | 「第 3 行按我说的改成 XXX」 | 按你的口径修正并重算金额 |
| **③ 确认** | **「确认台账，开始归档」** | ⚡ 才真正动手建发票目录、复制并重命名文件 |
| **④ 出清单** | 「给我最终的目录清单」 | 输出树状结构 + 每行的票据/附件对照表 |

**关键分界线**：只有当你明确说「确认 / 认同这个识别结果 / 开始归档」，我才会碰文件。说「先看看」「再想想」都视为未确认。

## 五、我会主动停下来问你的五件事

这几件事我不会替你决定：

1. **Grab 疑似私人行程** — 非通勤路线、异常时段的记录（如去巴士站、商场），我会列出来问你要不要剔除；你确认后我在台账标注「私人行程，未计入」。
2. **汇率截图映射表** — 每张截图对应哪个币种对，请你核对确认。
3. **作废 / 重复凭证** — 同一笔消费出现两张金额不同的支付截图时，我会说明判断依据（以与订单金额一致的为准），请你拍板。
4. **专车合并还是单独成行** — 我会给出勾稽算式（机票 A + 专车 B ?= 支付 C）和结论，请确认。没有专车支付截图时我会直接问你。
5. **出差区间含法定节假日** — 补助默认不扣节假日，但我会在台账表格里打 ⚠️ 列出具体日期，请确认扣还是不扣。

## 六、每一步你会拿到什么

**第 2 步结束后**（核验阶段）：

```
报销材料核验台账-<行程区间>.md
├── 一、报销单预览表   ← 几行报销记录？每行金额多少？票据/附件分别是什么
├── 二、Grab 逐笔台账  ← 每笔日期/时间/路线/金额，加总与对账单校验
├── 三、材料核验明细   ← 每份文件：有效 / 作废 / 重复 / 缺失
└── 四、定稿说明       ← 汇率依据、修正记录、版本历史
```

**第 4 步结束后**（归档阶段）：

```
发票目录-<行程区间>/
├── 01-飞机含专车-HKD2873.00/
│   ├── ★票据本体/     ← 稽核时真正看的核心凭证
│   └── ☆附件/         ← 支付截图、订单凭证、汇率截图（按上传顺序编号）
├── 02-住宿3557-HKD2606.14/
├── 03-住宿5679-HKD4189.05/
├── 04-住宿1296-HKD3108.27/
├── 05-Grab其他交通-HKD1149.01/
└── 06-补助-HKD9996.00/
```

**一条报销记录 = 一个文件夹**，`★票据本体` 与 `☆附件` 分开，上传时照着拖就行。

> 上图是**专车合并形态**（一笔支付 = 机票 + 专车）的示例。若判定为两个独立订单，会拆成 `01-飞机-HKxxxx` 和 `02-专车-HKxxxx` 两个文件夹。

## 七、规则文件：你可以自己改

规则全部是可读的 Markdown，改完下次执行立刻生效，不用改代码。

| 文件 | 什么时候该改 |
|---|---|
| `references/文件识别规则.md` | 换了凭证来源、发现新的 OCR 坑、新增文件类型 |
| `references/账单分类与勾稽规则.md` | **补助日标准变了**（如 75 → 80 USD/天）、专车改单独成行、勾稽口径调整、**补助周末/节假日是否计入的开关** |
| `references/报销单填写逻辑.md` | 用友报销单字段调整、票据/附件划分口径变化 |
| `references/节假日日历.md` | **每年 11 月**国务院发布次年安排后更新；公司若按香港假期，整体替换 |
| `scripts/calc_subsidy.py` | 一般不用改；算法开关都在 `账单分类与勾稽规则.md` 第四节 |

直接跟我说「把补助日标准改成 80 美元，更新规则文件」，我来改。

## 八、几条硬规矩

- **原始文件只读**：归档时只复制，你的 Downloads 目录保持原样。
- **未确认不动手**：见第四节的确认口令。
- **加总必须对齐**：Grab 逐笔加总要等于对账单合计（允许 ±0.01）；对不上我会高清重读 OCR，绝不强行调平。
- **报销单默认存草稿**：去用友平台填写前会先问你，且默认不提交。

## 九、给同事：怎么装上这个 skill

拿到 `invoice-organizer-vX.Y.Z.zip` 后：

1. **解压**，得到 `invoice-organizer/` 文件夹（内含 SKILL.md、README.md、CHANGELOG.md、references/）。
2. **放到 skills 目录**，二选一：
   - **只给自己用**（用户级）：`~/.workbuddy/skills/invoice-organizer/`
   - **整个团队共用**（项目级）：`<项目目录>/.workbuddy/skills/invoice-organizer/`
3. **重启或新开一个会话**，让它重新加载 skill。
4. 确认装好：直接问「帮我整理发票」，看它会不会先声明受理范围（第 0 步）。

**动手前建议先读**：`README.md` 第三节（材料清单）、第四节（命令速查）。
**规则想改**：直接改 `references/` 里的三个文件，改完下次执行立刻生效，不用改代码。
