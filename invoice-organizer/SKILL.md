# 发票整理（差旅报销凭证核验与归档）

## 受理范围（第 0 步，每次启动必须先声明）

仅接受以下 7 类报销凭证，启动时先向用户声明此范围，范围外凭证不予处理：

1. **携程飞机票**（机票订单确认邮件/订单详情、中英版行程单、支付截图；**须核退款**——实报以退款后金额为准）
2. **携程机票改签**（2026-10-04 新增：改签发票 ITINERARY/INVOICE + 改签费用详情截图 + 改签后行程单 + 支付截图（**有几笔支付就要几张**）；**实报以「发票 TOTAL / 订单详情页总计」为准**，行程单金额会少一张改签手续费；**若同一订单同时存在退款，按「支付合计 − 已退款」取净额**——见第七节第 6 条。**主动识别、主动索要缺料，同一订单只出一行**）
3. **携程酒店**（酒店水单、入住证明、支付截图）
4. **携程专车**（用车行程单、用车电子发票、支付截图；**是否并入飞机行由支付凭证勾稽决定**：支付截图金额 = 机票 + 专车 → 合并一行；两笔支付分开 → 专车单独成行）
5. **滴滴用车**（滴滴出行行程报销单 + 滴滴电子发票 + 支付截图；**行程单金额 + 高速费 = 支付金额 = 实报金额**）
6. **Grab 流水**（Grab Member Statement 对账单 + 逐笔台账）
7. **出差补助**（手录行程，无票据本体，仅需汇率截图）

## 工作流（严格遵守顺序，第 2⇄3 步可多次循环）

### 第 1 步：接收凭证清单
- 用户提供行程消费凭证（文件夹路径或文件列表）。先 `ls` 全量列出，不遗漏、不臆测。

### 第 2 步：识别与核验 → 生成初版台账
按 `references/文件识别规则.md` 逐份识别文件，按 `references/账单分类与勾稽规则.md` 做勾稽核对，然后向用户报告：
- **缺失文件**：按 7 类凭证的必备清单逐项比对，列出缺料；
- **勾稽不符**：金额/日期/订单号对不上的条目，给出具体差异数值；
- **退款核验（携程）**：确认单/订单详情页若出现「已退款」，实报金额 = 订单总额 − 已退款，须与行程单票价合计三方对齐；支付截图金额**不等于**实报金额，不得直接用支付金额报销；
- **改签核验（携程机票，2026-10-04 新增）**：改签订单会出现**两张不同总额**，务必区分，**别拿行程单金额去报**：
  - **改签发票 TOTAL / 订单详情页「总计」**（含 `FARE 机票款 + TAX 税费 + CHANGEFEE 改签费 + PRICE DIFFERENCE 差价 + Tax Difference 税差`）= **实报依据**；
  - **行程单总计**（= 改签后票价 + 税费）= 少一张 **CHANGEFEE 改签手续费**，只说明最终票价，**不得作报销依据**；
  - 勾稽链（全部要跑）：① `原票款支付 = FARE + TAX`；② `改签支付 = CHANGEFEE + PRICE DIFFERENCE`；③ `两笔支付合计 = 发票 TOTAL = 订单详情页总计`；④ `行程单票价 = FARE + PRICE DIFFERENCE`；⑤ `行程单总计 + CHANGEFEE = 发票 TOTAL`；⑥ 改签费用详情页（改期手续费/机票差价/税差）三项之和 = 改签支付金额；⑦ 新旧航班对照（原航班 vs 新航班日期时间）须与改签详情页一致；
  - ⚠️ **报销范围必须问用户**：报**整单（原票款 + 改签费，= 发票 TOTAL）**，还是**仅改签新增部分（= CHANGEFEE + PRICE DIFFERENCE）**（前提：原票款已在其他批次报过）。**不得自行假定**；
  - 备注写明组成，示例：`改签订单ORDER-EXAMPLE,原票款4176(机票款2867+税费1309)+改签费1040(手续费450+差价590)=5216,汇率为5216/0.8584=6076.42`
- **同一订单只出一行（2026-10-04 新增，硬性）**：报销单预览表里，**同一个携程 ORDER ID 只占一行**，不得按费用性质拆行：
  - 机票本金、改签手续费、机票差价、税费、燃油附加费、退款冲减 —— 全部并进**同一条记录**；
  - 多次改签 = 多笔改签支付，仍在同一行累加，备注里逐次写清（`-n0501改签1040-` 这样）；
  - **票据本体** = 该行最能独立证明最终金额的那一份（有最终发票取发票；有退款时优先取**订单详情页，因为它同时露出应付与已退款**）；其余全部进附件（可在附件里重复出现）；
  - 特别注意：**退款不做负数行**，而是在本行里减掉，最后只体现净额。
- **改签类缺料必须主动索取（2026-10-04 新增）**：改签订单给用户材料时往往只给行程单或部分截图，须逐项比对下列清单，**缺哪样就明确开口要，不要等用户问**（支付截图看不到退款、行程单看不到改签费、订单详情页最容易漏）：
  | 必取材料 | 缺了会怎样 |
  |---|---|
  | 改签发票（ITINERARY/INVOICE，含 PAYMENT DETAILS 六项） | 不知道 CHANGEFEE / PRICE DIFFERENCE 各自多少 |
  | 「核对改签费用」详情截图（改期手续费/机票差价/税差） | 无法验证改签支付金额 |
  | 改签信息截图（新航班 vs 原航班） | 无法确认改签前后日期，行程单是否已更新也无从判断 |
  | 订单详情页（**最重要，退款只在这里露出**） | 有退款却不知道 → **直接多报** |
  | 逐笔支付截图（原票款 + 每次改签各一张） | 无法做「支付合计 = 发票 TOTAL」勾稽 |
  | 改签后行程单 | 缺少最终票价/税费佐证 |
- **高速费核验（滴滴）**：行程单金额 + 高速路桥费 = 支付金额 = 实报金额；高速费在「费用说明」页单列，行程单的金额列不含它，两边都要取到；
- **Grab 私人行程**：列出疑似私人行程（非通勤路线、异常时段），**必须询问用户是否剔除**，不得自行决定；
- **汇率映射表**：把目录下没被认作消费凭证的图片逐张打开（**不以文件名前缀筛选**，`SCR-` 只是本机截图工具的默认命名），肉眼确认内容后列出「文件名 ↔ 币种对 ↔ 数值 ↔ 来源」并请用户确认——严禁凭假设归类；
- **核对报价方向**：截图可能写成「1 HKD = X 外币」（反向报价）。反算逻辑保留可用（取倒数，如 `1 USD = 1 ÷ 0.1274 ≈ 7.85 HKD`；页面大字为四舍五入值时读走势图末点做刻度线性映射），但 **⚠️ 反算结果一律不得直接采用——必须二次确认**：① 在台账列出截图原文与完整换算过程；② **停下来请用户提供直接报价截图或明确认可该反算值**；③ 用户确认后方可用于折算与归档；
- **补助天数**：跑 `scripts/calc_subsidy.py` 逐日展开计算，明细并入台账；若区间跨越法定节假日，**必须在台账表格内**标注 ⚠️ 并列出日期节日，请用户二次确认——不得只在对话里提一句；
- **周末 / 节假日是否加班（2026-10-04 新增，硬性）**：出差区间内的**每一个周末日和法定节假日**，都要主动提醒用户确认当天是否正常加班：
  - 用户答「**是（加班）**」→ 当天**照计补助**；但若当天恰为**出发日或到达日，仍只记 0.5 天**（半天规则优先级更高）；
  - 用户答「否」→ 周末计 0，节假日按 `DEDUCT_HOLIDAY` 开关走；
  - 输出时这些行的「是否加班」列先写 **待确认**，并在**台账表格内**列出具体待确认日期；**不得默认「周末没加班」直接定稿**；
  - **答「这几天上班」时必须先确认覆盖范围**（2026-10-04 教训）：像「09-25 这几天上班了」这类模糊表述，可能指 1 天也可能含后续周末；**先列出候选日期让用户勾选，再改金额**，避免按错误天数返工；
- **确认结果回写闭环（2026-10-04 新增）**：用户答复加班/休假后，① 同步更新逐日台账 txt **与**核验台账 MD（逐日表格「是否加班」列、报销单备注文案、用户确认结论表、修正记录）；② **清除两份文件里所有「待确认」标记**；③ 明确写出**天数与金额是否变化**（无变化也要写「金额无变化，仍 X 天 / HKD Y」）；④ 若天数变化，同步改**归档文件夹名中的金额**（`08-补助-HKDxxxx.xx`）与总计、归档清单.md、逐日 txt；
- **补助逐日台账 txt**：按「日期 ｜ 星期 ｜ 假期/调休 ｜ 是否加班 ｜ 补助天数(0.5/1) ｜ 说明」逐日一行生成，文件尾部附**加班/休假确认记录**（哪天上班、哪天休息、结论金额），**必须作为补助行附件归档**（见第 4 步）；
- 生成初版《报销材料核验台账》MD 文件（含报销单预览表、逐笔台账、材料核验明细、修正记录四部分）。

### 第 3 步：用户补充材料
- 用户补充文件或给出口径修正后，回到第 2 步重新识别核验，更新台账版本号（v0.1 → v0.2 …）。此循环可能重复多次。

### 第 4 步：用户确认 → 分类归档
- 仅在用户明确说「认同/确认识别结果」后执行：
  1. **归档目录必须建在原始凭证目录内部**（即用户第 1 步给的那个文件夹里），命名 `发票目录-<行程区间>/`；**不要建在工作区或其他位置**。理由：材料与归档结果同处一处，用户直接从原材料目录上传即可，不必跨目录找文件。若原始目录不可写或用户另有指定，须先确认再执行；
  2. **每条报销行一个文件夹**（`01-类型-关键信息-HKD金额/`），文件夹内分 `★票据本体/` 与 `☆附件/` 两个子目录；
  3. **只复制、绝不移动或删除**用户 Downloads 等个人目录中的原始文件；
  4. 附件按上传顺序编号重命名（`01-内容-金额.扩展名`）；重复文件（带 `(1)`）只留一份；
  5. Grab 行的逐笔台账 CSV 生成到该行 `☆附件/` 下（UTF-8 BOM，Excel 打开不乱码）；
  5-补. **补助行的逐日台账 txt 生成到该行 `☆附件/` 下**（命名 `02-补助逐日台账-<区间>.txt`，位于汇率截图之后）。补助行无票据本体，天数全靠这份明细佐证，**上传用友时须一并上传**；
  6. 在归档目录根部生成 `归档清单.md`（上传顺序总表 + 逐行明细 + 未归档文件说明 + 勾稽结论），供上传平台时对照；
  7. 复制完成后**用 md5 抽检关键文件**（票据本体、汇率截图）确认归档副本与源文件一致，防止复制错文件——历史上出过汇率截图张冠李戴的事故。

### 填写报销单 / 发票池（可选后续）
- 报销单字段填写逻辑见 `references/报销单填写逻辑.md`。默认**存草稿不提交**，等平台操作获用户明确授权后再执行。
- **推荐路径**：目录归档完成后，先用 `yonyou-invoice-pool` skill 把整个目录录进用友「发票池（含收据）」的一个票袋，
  再在报销单里从该票袋整袋勾选拉取——比在报销单内逐行「添加账单」更稳，且票袋可复用、可核对。
- 两者分工：本 skill 管**目录整理与核验**，`yonyou-invoice-pool` 管**发票池票袋录入**，
  报销单表头/TAPL 关联/提交归本 skill 的 `报销单填写逻辑.md`。

## 用户使用说明

面向用户的材料准备清单与指令口令见 `README.md`。用户若不清楚该给什么材料、或不知如何推进到下一步，先让其阅读 `README.md` 第三节（材料清单）与第四节（命令速查），并按其中的口令确认（确认归档的口令是「确认台账，开始归档」）。

## 规则文件（用户可手工维护，改动即生效）

| 文件 | 内容 |
|---|---|
| `references/文件识别规则.md` | 各类凭证的识别特征、OCR 技巧、作废/重复判定 |
| `references/账单分类与勾稽规则.md` | 7 类凭证的必备材料清单、金额勾稽关系（**含退款核验、改签核验、滴滴高速费**）、私人行程判定、**补助工作日算法（含开关）** |
| `references/报销单填写逻辑.md` | 用友报销单字段口径、票据本体 vs 附件划分、汇率凭证搭配规则 |
| `references/节假日日历.md` | 法定节假日与调休上班日，每年 11 月更新；DATA 区块供脚本读取 |
| `scripts/calc_subsidy.py` | 补助天数计算器，输出逐日明细、金额折算与节假日提醒 |

执行补助行核验时，直接跑 `python3 scripts/calc_subsidy.py <出发日> <返回日> --rate 75 --fx <汇率>`，把逐日明细并入台账，不要口算。

执行任何步骤前，先读取对应的规则文件；若用户口头给出的新规则与文件冲突，以用户口径为准并提示是否同步更新规则文件。

## 硬性原则

- **两步式确认**：先出核验台账 → 用户确认 → 再归档命名；未确认前不做任何文件操作。
- **原始文件只读**：所有归档动作为复制，源目录保持原样。
- **数据自校验**：逐笔加总必须等于对账单合计（允许 ±0.01 尾差），不等时高清重渲染复核 OCR，不得强行通过。
- **汇率留痕**：每个币种记录汇率来源截图文件名与取值，CNY 用中行折算价、MYR/USD 用 Google 汇率。
- **补助只算工作日**：出发日、落地日各半天，**周末一律不计**，节假日默认不扣但必须在台账表格内提醒用户二次确认。天数逐日展开计算，禁止用「总天数减周末」估算。
- **退款后才是实报金额**：携程类凭证（机票/酒店/用车）只要存在退款，报销金额一律取**退款后净额**，支付截图金额只作附件佐证；退款凭证必须一并归档。
- **改签取总额、退款取净额（方向相反，别混）**：改签订单的实报依据是**发票 TOTAL / 订单详情页总计**（= 原票款 + 改签手续费 + 差价），**不是**改签后行程单的金额（行程单不含改签手续费，会少报）；报销范围（整单 vs 仅改签新增）必须先问用户。
- **同一订单一行（2026-10-04 新增）**：一个携程 ORDER ID = 一条报销记录。票款、改签手续费、机票差价、税费、燃油、退款冲减全部并进同一行，净额体现，**退款不单独做负数行**；多次改签也只累加不拆行，备注里逐次写清算式。
- **缺料主动索要，不等用户追问（2026-10-04 新增）**：识别出改签订单后，逐项比对必备清单（发票六项拆解 / 改签费用详情 / 新旧航班 / 订单详情页 / 逐笔支付 / 改签后行程单），缺哪样当场开口要。**尤其订单详情页——退款只在那里露出，漏了就会多报。**
- **高速费单列**：滴滴行程单金额不含高速路桥费，实报金额 = 行程单金额 + 高速费 = 支付金额；三者不等时必须查清后才能出账。
