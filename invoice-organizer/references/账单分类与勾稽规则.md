# 账单分类与勾稽规则

> 本文件由用户手工维护。修改后下次执行即生效。
> 最近更新：2026-09-07（新增第四节补助工作日算法 + 节假日提醒机制）
> 初版依据：2026-09-05（0720-0806 吉隆坡出差核销实践整理）

## 一、各类凭证必备材料清单

| 类别 | 票据本体（核心凭证） | 必备附件 | 汇率凭证 |
|---|---|---|---|
| 飞机（含专车） | 订单确认邮件 | 支付截图 + 机票行程单 + 专车行程单 + 邮件原文件 | 中行牌价截图（CNY） |
| 酒店（每段订单一行） | 酒店水单 | 入住证明 + 水单原文件 + 支付截图 | 中行牌价截图（CNY） |
| 专车（**独立成行时**，见第二节第 3 条） | 用车行程单 | 支付截图 | 中行牌价截图（CNY） |
| Grab 流水 | Member Statement 对账单 | Google 汇率截图 + 逐笔台账 CSV | Google 汇率截图（MYR） |
| 补助 | （无票据本体） | Google 美元汇率截图 | Google 汇率截图（USD） |

## 二、勾稽核对关系

1. **飞机行**：订单邮件总额 = 机票价 + 附加服务费 = 支付截图金额；行程单票价 = 订单中机票部分。
2. **酒店行**：水单金额 = 支付截图金额；入住证明尾号 = 水单订单尾号；多段连住每段独立一行。
3. **专车与飞机是否合并**：**以支付凭证勾稽结果判定，不得默认合并**（2026-09-06 修订）。
   设 机票订单金额 = A、专车行程单金额 = B、支付截图金额 = C：

   | 勾稽结果 | 说明 | 处理 |
   |---|---|---|
   | **C = A + B** | 一笔支付同时覆盖机票与专车 → **同一个携程订单** | **合并成一行**：金额 = A + B；票据本体 = 机票订单确认邮件；专车行程单列入附件；备注注明「含 MMDD 携程专车送机」 |
   | **C = A**（专车另有独立支付），或 **C = B** | 两笔支付分开 → **两个独立携程订单** | **分别成行**：飞机行、专车行各自独立；专车行票据本体 = 用车行程单，两行各配自己的支付截图 |

   - 出现多张支付截图时，先按《文件识别规则》的「作废凭证判定」确定有效凭证，再做上述比对。
   - 判定结论与勾稽算式必须写进台账，并请用户确认后才归档。
4. **Grab**：逐笔加总必须 = 对账单合计（±0.01）；剔除私人行程后得到报销小计；对账单可直接作票据本体。
5. **补助**：**按工作日计**，天数算法见第五节（出发日 0.5 + 中间工作日 + 返回日 0.5，周末剔除，节假日不自动扣但须提醒用户确认）；金额 = 天数 × 日标准（当前 75 USD/天）。

## 三、Grab 私人行程判定（须用户确认）

疑似私人行程特征：
- 路线非「住所 ↔ 职场」通勤（如去车站、商场、景点）；
- 异常时段（深夜、周末非加班日）；
- 用户事先声明的私人安排。

处理：**列出疑似条目 → 询问用户 → 确认后在台账标「否/私人行程，未计入报销」**，并在 Grab 行备注中写明「其中MMDD XX行程 NN.NN 为私人行程，未计入」。

## 四、补助天数算法（只看工作日）

> 2026-09-06 修订：周末不计入；节假日不自动扣减，但须在台账提醒用户二次确认。
> 配套文件：`references/节假日日历.md`（放假安排，每年 11 月更新）
> 配套工具：`scripts/calc_subsidy.py`（可直接跑，输出逐日明细与节假日提醒）

### 1. 逐日规则

| 日期 | 名义天数 | 是否计入 |
|---|---|---|
| 出发日 | 0.5 | 逢工作日计入；**逢周末计 0**（见开关 S2） |
| 中间日 | 1.0 | 仅**工作日**计入，周末计 0 |
| 返回日 | 0.5 | 同出发日 |

- 出发日 = 返回日（当日往返）时，合计 1.0 天。
- **调休上班日**（日历里标 `workday` 的周末）按工作日计入。
- 计算必须**逐日展开**，不能拿「总天数 − 估算周末数」估算——跨周时极易算错。

### 2. 可调开关（改这里就生效）

| 开关 | 默认 | 含义 |
|---|---|---|
| `DEDUCT_HOLIDAY` | `false` | `false` = 节假日不扣天数，只提醒确认；公司明确不发时改 `true` 自动扣除 |
| `WEEKEND_TRAVEL_DAY` | `false` | `false` = 出发/落地日逢周末计 0；若公司政策允许 travel day 计半天，改 `true` |

对应脚本参数：`--deduct-holiday`、`--weekend-travel-day`。

### 3. 节假日提醒（必做）

算出天数后，拿 `references/节假日日历.md` 比对出差区间：

- 区间**跨越**法定节假日 → 补助行打 **⚠️** 并列出具体日期与节日名，**请用户二次确认**是否计入；台账里要写明「区间含 XX 节日 X 天，当前未扣除，待确认」。
- 区间**不含**节假日 → 台账注明「区间内无法定节假日」即可。

> 提醒必须落在**输出的表格里**（补助行备注或单独一行提示），不能只在对话里说一句。

### 4. 算例（0720-0806 吉隆坡）

```
python3 scripts/calc_subsidy.py 2026-07-20 2026-08-06 --rate 75 --fx 7.84
→ 计入 13.0 天 = USD 975.00 = HKD 7,644.00
  （旧口径含周末为 17 天 / USD 1,275.00，差 4 天，来自 07-25、07-26、08-01、08-02 两个周末）
```

## 五、汇率与折算口径

| 币种 | 汇率来源 | 折算方向 | 示例 |
|---|---|---|---|
| CNY | 中行外汇牌价（港币折算价） | 原币 ÷ 折算价小数 = HKD | 2,484 ÷ 0.8646 = 2,873.00 |
| MYR | Google 汇率 | 原币 × 汇率 = HKD | 595.34 × 1.93 = 1,149.01 |
| USD | Google 汇率 | 原币 × 汇率 = HKD | 1,275 × 7.84 = 9,996.00 |

- 汇率取值日：通常为提交前一两天，截图文件名须记录在台账「汇率依据」中。
- **汇率映射强制确认**：每张汇率截图必须逐张视觉读取，在台账中列出「文件名 ↔ 币种对 ↔ 数值 ↔ 来源」映射表并请用户确认；SCR 文件名的随机码不含币种信息，不得凭假设归类（教训：2026-09-05 skfe/sjyj 互换事件）。
- 报销货币一律 **HKD**；报销单计价货币为 USD（平台设置，不影响逐行折算）。
- 报销金额保留两位小数，四舍五入。
